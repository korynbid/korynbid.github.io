[ADS-FINAL-PREP] 15. Hash Tables

Oct 24, 2026 · Algorithms & Data Structures · Author: Archiveskk · Source: https://t.me/c/2310214877/1713/1733

Description

A Hash Table is a data structure that enables efficient insertion, deletion, and lookup operations. It works by utilizing a hash function, which converts a key into an index in an array where the corresponding value is stored. This allows data access in amortized O(1) time complexity in most cases.

Hash tables are widely used across various applications such as databases, caches, data analytics, and many other domains requiring fast key-based data lookup.

Core Hash Table Operations

  1. Insert: Adding a new element (key-value pair) to the hash table.
  2. Delete: Removing an element by its key.
  3. Search (Lookup): Finding an element by its key.
  4. Collision Handling: When two distinct keys hash to the same index, a collision occurs. Various techniques, such as chaining or open addressing, are used to resolve collisions.

How a Hash Table Works

  1. Hash Function: The hash function takes a key and converts it into an array index. A good hash function distributes keys uniformly across the array to minimize collisions.
  2. Array Storage: An array is used to store the elements. Each table slot holds a key-value pair, where the key is unique.
  3. Collisions: If two different keys map to the same array index, a collision happens. Collisions can be managed using strategies like separate chaining or open addressing.
class HashTable:
    def __init__(self, size=10):
        self.size = size
        self.table = [None] * size

    def _hash(self, key):
        return hash(key) % self.size

    def insert(self, key, value):
        index = self._hash(key)
        if self.table[index] is None:
            self.table[index] = [(key, value)]
        else:
            for idx, (k, v) in enumerate(self.table[index]):
                if k == key:
                    self.table[index][idx] = (key, value)
                    return
            self.table[index].append((key, value))

    def search(self, key):
        index = self._hash(key)
        if self.table[index] is not None:
            for k, v in self.table[index]:
                if k == key:
                    return v
        return None

    def delete(self, key):
        index = self._hash(key)
        if self.table[index] is not None:
            for i, (k, v) in enumerate(self.table[index]):
                if k == key:
                    del self.table[index][i]
                    return True
        return False

    def __str__(self):
        return str(self.table)

Code Explanation

  1. __init__(self, size):
  2. Constructor that initializes the hash table with a specified size. The self.table array stores the entries/buckets.
  1. _hash(self, key):
  2. The internal hash function that converts a key into an array index. It uses Python's built-in hash() function to derive a numeric hash value and then applies the modulo operator (%) with the table size to determine the array index.
  1. insert(self, key, value):
  2. Method for inserting elements into the table. It calculates the target index using the hash function. If elements already exist at this index (due to a collision), they are appended to a chain (list). If the key already exists in the chain, its value is updated.
  1. search(self, key):
  2. Method for looking up an element by key. It checks the calculated bucket index and traverses the chain at that slot to locate the key.
  1. delete(self, key):
  2. Method for removing an element by key. If found, the corresponding key-value pair is removed from the chain.
  1. __str__(self):
  2. String representation method that formats the hash table for convenient display and logging.

Collision Resolution Techniques

  1. Chaining (Separate Chaining):
  2. When multiple keys hash to the same index, they are stored within a linked list (or other dynamic collection) at that slot. This method is simple and effective, though it increases dynamic memory usage.
  1. Open Addressing:
  2. When a collision occurs, the algorithm searches for another open slot in the array using a probing sequence (e.g., linear probing or quadratic probing). This avoids extra memory allocations outside the main array but complicates search and deletion logic.

Advantages of Hash Tables

  1. High Performance: On average, insertion, lookup, and deletion operations run in O(1) time complexity, making hash tables one of the fastest data structures for key-based retrieval.
  2. Flexibility: Hash tables can accept virtually any data type as keys provided a suitable hash function is available.
  3. Widespread Industry Adoption: Extensively utilized in real-world systems, including caching layers, database indexing, set implementations, and associative dictionaries.

Disadvantages of Hash Tables

  1. Collisions: Hash functions may unevenly distribute elements, causing collisions that require extra processing and reduce overall performance.
  2. Unordered Data: Hash tables do not maintain element insertion order or sorted key order (unlike trees or ordered lists).
  3. Memory Considerations: Open addressing techniques require careful sizing; a high load factor can severely degrade lookup speeds and increase allocation needs.

Applications of Hash Tables

  • Caching: Fast key-value lookups in caching layers (e.g., in-memory key-value stores).
  • Set Implementation: Storing unique items efficiently in standard programming libraries.
  • Searching and Indexing: Accelerating record lookups in database indexes and search engine indices.
  • Data Analytics: Rapidly processing, grouping, and aggregating large-scale datasets.

Conclusion

Hash tables are among the most powerful and performant data structures for lookup, insertion, and deletion operations. Achieving optimal performance requires an appropriate hash function and effective collision resolution. Consequently, hash tables are an indispensable building block in modern software systems and algorithms handling high-volume data.
