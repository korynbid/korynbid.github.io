14. Warehouse-Scale Computers (WSC)

Oct 25, 2026 · COMPARCH · Computer Architecture · Author: Algo-holics · Source: https://t.me/kbtukbtu/583

Description

A warehouse-scale computer is a huge data center (tens of thousands of servers) built to run a few large internet services and cloud workloads (search, video, email, cloud rentals) as one giant computer. Examples: Google, Amazon (AWS), Microsoft (Azure) data centers.

Key characteristics:

  • Scalability: serve millions of users by adding servers.
  • Request-level and data-level parallelism: independent requests run in parallel (RLP) and big datasets are processed in parallel (DLP).
  • Cost-performance and energy efficiency: at this scale electricity, cooling and hardware purchase dominate cost.
  • Dependability through software: with so many components, failures are constant; software replicates data and retries tasks instead of relying on perfect hardware.
  • Network I/O and interactive latency: services must answer quickly; tail latency (the slowest responses) matters.

Architecture:

LayerRole
ServerCPU, DRAM, local disk/SSD, commodity parts
Rack~40-80 servers + top-of-rack (ToR) switch
Array / clusterRacks joined by aggregation (array) switches
Core networkConnects arrays and the outside world
StorageDistributed file systems (e.g. Google File System) with replication; SSD, HDD, NVMe
Memory hierarchy viewLocal DRAM → rack DRAM → array DRAM → disk, each level adding latency; Fibre Channel/array switches connect storage

Programming models and workloads:

  • MapReduce: map applies a function to input pieces in parallel, a shuffle groups results by key, reduce combines each group. Example: counting words in a huge text corpus.
  • MPI (Message Passing Interface): explicit communication between nodes; typical in scientific simulation and HPC.
  • Workloads: video streaming, search, storage, big-data analysis, machine learning.

Power, cooling and efficiency: servers → power distribution (transformers, UPS batteries, generators) → cooling (air, chilled water, liquid cooling). PUE = total facility power / IT power; Google reports about 1.1 for its data centers.

Cloud computing: renting compute, storage and services over the Internet (IaaS, PaaS, SaaS), enabled by WSC economies of scale and virtualization (Topic 8). Example: renting virtual machines on AWS.

Key Formulas

PUE = Total facility power / IT equipment power

Availability  = uptime / total time;     downtime/year = (1 − availability) × 525,600 min

Oversubscription ratio = (total downlink bandwidth) / (uplink bandwidth)

Tail-latency amplification (fan-out N, each server slow with prob. p):
   P(at least one slow) = 1 − (1 − p)^N

Replication:  usable capacity = raw capacity / replication factor

Annual energy cost = power (kW) × 8760 h × price ($/kWh)

Steps

Estimate WSC electricity: (1) IT power per server × servers, (2) multiply by PUE, (3) × 8760 h, (4) × price.

Run a MapReduce job: (1) split input into chunks, (2) run map tasks on chunks in parallel, (3) shuffle by key, (4) run reduce tasks, (5) re-execute failed or slow tasks elsewhere.

Worked Example

A. Downtime. 99.99% availability → 0.0001 × 525,600 = 52.6 minutes per year; 99.9% → 526 minutes (8.8 hours).

B. Tail latency. A search request fans out to 100 servers; each is slow (e.g. a garbage-collection pause) 1% of the time: P(at least one slow) = 1 − 0.99¹⁰⁰ = 63.4%. So the user sees the slow case more often than any single server does.

C. Oversubscription. Rack with 40 servers × 10 Gb/s = 400 Gb/s down; 4 × 40 Gb/s = 160 Gb/s up → 2.5:1. Traffic between racks is limited to 40% of rack capacity, so schedulers keep communicating tasks inside the same rack when possible.

D. Server energy cost. 300 W server, PUE 1.2: 360 W at the wall → 360 × 8760 / 1000 = 3153.6 kWh per year × $0.08 = about $252 per year. A $5,000 server amortized over 4 years costs $1,250 per year, so power is roughly 17% of that server's running cost, not negligible but not dominant either.

E. PUE. At PUE 1.1, 10 MW of IT load needs 11 MW; at PUE 1.5 it needs 15 MW. The 4 MW difference over a year is 4 × 8760 = 35,040 MWh.

F. Replication. 30 PB raw with 3× replication → 10 PB usable. Replication makes data survive disk, server and even rack failures.

G. MapReduce word count. Input: "to be or not to be". Map → (to,1), (be,1), (or,1), (not,1), (to,1), (be,1). Shuffle groups by word. Reduce → to:2, be:2, or:1, not:1.

Python / Assembly

from collections import defaultdict

def map_fn(line):
    for w in line.lower().split():
        yield (w, 1)

def reduce_fn(word, counts):
    return (word, sum(counts))

def mapreduce(lines):
    groups = defaultdict(list)                 # "shuffle"
    for line in lines:
        for k, v in map_fn(line):
            groups[k].append(v)
    return dict(reduce_fn(k, vs) for k, vs in groups.items())

print(mapreduce(["to be or not to be"]))       # {'to': 2, 'be': 2, 'or': 1, 'not': 1}

def downtime_min_per_year(avail):
    return (1 - avail) * 525_600
print(round(downtime_min_per_year(0.9999), 1))     # 52.6
print(round(1 - 0.99**100, 3))                     # 0.634

Notes

  • Data-center energy: some sources state that servers and cooling use about 86% of energy (see Topic 4 note); the safest view is PUE-based: overhead beyond IT is typically 10-50% depending on facility efficiency.
  • WSC fallacies: overestimating what a single server can do for big jobs (ignoring network latency), scaling problems, and under-built cooling for new servers.
  • WSC vs HPC: WSCs favor independent requests on commodity hardware and software fault tolerance; supercomputers use tightly coupled nodes and fast interconnects (MPI).
  • Slow-node mitigation (backup tasks in MapReduce, hedged requests) fights the tail.
  • Quick facts: PUE measures data-center energy efficiency; strategies include virtualization, cooling optimization and renewables; AI can optimize workloads and cooling.
