[ADS-FINAL-PREP] 20. Edge List

Oct 24, 2026 · Algorithms & Data Structures · Author: Archiveskk · Source: https://t.me/c/2310214877/1713/1733

Description

An edge list is a graph representation method where all edges of a graph are stored as a list, with each edge represented as a pair of vertices that it connects. This is one of the simplest and most compact representations of a graph, often used when it is necessary to operate directly on edges rather than vertices or their neighbors.

An edge list is particularly useful when processing graphs where direct edge operations are crucial—such as listing or analyzing all edges—without requiring fast lookup for a specific vertex's neighbors. It is ideal for storing graphs where edges lack attributes or weights, or for sparse graphs with a relatively small number of edges.

1. Edge List Structure

In an edge list, each edge is represented by a pair (or tuple) of vertices. For a directed graph, an edge (u, v) denotes a directed edge going from vertex u to vertex v. For an undirected graph, an edge (u, v) can also implicitly represent the edge (v, u).

Example for a Directed Graph

Suppose we have the following directed graph:

    0 -> 1
    |    ^
    v    |
    2 -> 3 -> 4

The edge list for this graph would be:

[(0, 1), (0, 2), (1, 3), (2, 3), (3, 4)]

Here, each element of the list is a tuple showing an edge between two vertices. Vertex 0 is connected to vertices 1 and 2, vertex 1 is connected to vertex 3, and so on.

2. Advantages of Edge List

  • Compactness: An edge list is a memory-efficient way to store a graph, especially if the graph is sparse.
  • Ease of Implementation: Simple to build and straightforward to maintain for storing graphs.
  • Suitable for Edge-Centric Operations: Particularly convenient when an algorithm focuses primarily on iterating through edges (e.g., Kruskal's algorithm for minimum spanning trees).

3. Disadvantages of Edge List

  • Slow Neighbor Lookups: Unlike an adjacency list, which allows retrieving all neighbors of a vertex in time proportional to its degree, an edge list requires scanning the entire list to find all edges connected to a given vertex.
  • Slow Modify/Delete Operations: Operations such as searching for or removing specific edges require traversing the entire edge list.

4. Applications of Edge List

An edge list is utilized across various graph processing tasks and algorithms:

  • Graph Traversal Algorithms: Algorithms such as Depth-First Search (DFS) and Breadth-First Search (BFS) can operate on graphs represented as edge lists (though with higher lookup overhead).
  • Minimum Spanning Trees: Algorithms like Kruskal's or Prim's rely directly on edge lists to evaluate and process graph edges in order of weight.
  • Shortest Path Search: Algorithms like Dijkstra's and Bellman-Ford can be implemented using edge lists.

5. Implementation of Edge List

An edge list can be created using standard dynamic sequences, such as a Python list or dynamic arrays in other programming languages. Each element is represented as a tuple containing two endpoints connected by an edge.

class Graph:
    def __init__(self):
        self.edges = []

    def add_edge(self, u, v):
        self.edges.append((u, v))

    def get_edges(self):
        return self.edges

    def display(self):
        for edge in self.edges:
            print(f"Edge: {edge[0]} -> {edge[1]}")

How the Code Works

  1. Graph Class: Represents the graph using an internal edge list (self.edges).
  2. add_edge(u, v) Method: Appends a new directed edge tuple (u, v) to the list.
  3. get_edges() Method: Returns the complete list of graph edges.
  4. display() Method: Prints each edge in the readable format "Edge: 0 -> 1".

6. Graph Operations on Edge List

Working with a graph stored as an edge list involves the following core operations:

  • Adding an Edge: Appending a new edge to the list takes O(1) time.
  • Removing an Edge: Searching for and deleting an edge takes O(e) time, where e is the total number of edges.
  • Finding Incident Edges: Locating all edges connected to vertex u requires scanning the entire list, taking O(e) time.

7. When to Use an Edge List

An edge list is most suitable in the following scenarios:

  • Storing sparse graphs where the total number of edges is relatively small compared to n^2.
  • When simple, minimal memory storage is required and frequent neighbor lookups for specific vertices are not needed.
  • For edge-centric algorithms, such as finding minimum spanning trees or processing global edge lists.

Conclusion

An edge list is a practical and simple data structure for representing graphs. It is particularly effective for sparse graphs and tasks where operating directly on edges is the main focus. However, for applications requiring rapid neighbor lookups or frequent edge presence checks between arbitrary vertices, an edge list is less efficient than an adjacency list or an adjacency matrix.
